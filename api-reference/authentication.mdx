Every pre.dev interface uses the same workspace key: specifications and browser tasks over REST, the AI Gateway at `/v1`, the SDKs, and the MCP server.

## Get your key

<ApiKeyLocation />

Each workspace, your personal account or a team, has one key. The Built-in tab shows it in full with its last-used time. Keep it in your application's secret configuration and call pre.dev from a server, a script, or local development. Never ship the key in browser or mobile code.

Apps you build on pre.dev already have the key in their environment as `PREDEV_API_KEY`; see [built into every app](/coding-agent/built-in).

Keys issued before workspace keys existed keep working. Use the `pdk_` key for new integrations.

## Send the key

| Interface | Send |
| --- | --- |
| REST and AI Gateway | `Authorization: Bearer <key>` (recommended) or `x-api-key: <key>` |
| MCP | Browser sign-in (OAuth) in interactive clients, or `Authorization: Bearer <key>`, `x-api-key`, or `predev-api-key` |

```bash
curl --fail-with-body https://api.pre.dev/browser-agent-status \
  -H "Authorization: Bearer $PREDEV_API_KEY"
```

The OpenAI SDKs send `Authorization: Bearer` and the Anthropic SDK sends `x-api-key`. The AI Gateway accepts both, so those SDKs need only a base URL and the key.

## Rotate the key

Choose **Rotate** on the key's card. The old key keeps working for 15 minutes, so running apps can switch without a gap. Update your secret store, then confirm a request with the new key succeeds before the window closes.

## Which accounts each interface accepts

Authentication and feature access are separate checks.

| Interface | Accepts |
| --- | --- |
| Browser Agents REST | Every account, including Free. Task submission then applies its own trial, credit, and queue checks. |
| AI Gateway | Every account, including Free. Free workspaces have a small lifetime allowance for gateway calls. |
| Architect REST and the MCP server | Personal accounts on a paid plan, and team workspaces |

A Free account can call Browser Agents and the AI Gateway, while an Architect REST or MCP call returns `401`. Which plans can generate specifications is covered in [plans, credits, and pricing](/coding-agent/plans-and-credits#api-and-mcp-access). Read the response message for the required action.

## Account and team context

A personal key acts in your personal account. A team key selects the team's context for specifications and credit usage. Browser history is scoped to the authenticated caller. Submit and retrieve work with the same key.

## SDK setup

<CodeGroup>
```typescript Node.js
import { PredevAPI } from 'predev-api';

const client = new PredevAPI({ apiKey: process.env.PREDEV_API_KEY! });
```
```python Python
import os
from predev_api import PredevAPI

client = PredevAPI(api_key=os.environ["PREDEV_API_KEY"])
```
</CodeGroup>

## MCP sign-in

Add `https://api.pre.dev/mcp` to your client's remote HTTP servers, then use the client's authentication flow. The browser asks you to sign in and choose the personal account or team to connect. [MCP setup](/architect-agent/mcp-setup) covers client configuration and troubleshooting.
