---
title: "Service API keys"
description: "Store reusable third-party credentials and apply updates to your projects."
---

Use the **API Keys** tab in [workspace Integrations](https://pre.dev/projects/integrations?tab=api-keys) for credentials your applications use, such as email, storage, or database keys. Values saved here reach your projects as environment variables.

Your **pre.dev API key**, which authenticates calls to pre.dev itself, is on the **Built-in** tab instead. See [authentication](/api-reference/authentication).

## Add a service credential

1. Open **Integrations → API Keys**.
2. Choose **Add key**, or **Import** to add several at once.
3. Enter the name and value, then save.
4. Open the target project's **Project setup → API Keys** to review the values it uses.

Keys are stored encrypted, and sensitive values are masked. Do not rely on a guarantee that arbitrary agent output can never expose a value.

## Import several keys

Use **Import** to paste configuration or upload a `.env`, `.txt`, or `.json` file, or a screenshot. Review the detected names and values before saving, especially for multiple environments or accounts.

## Apply and rotate

Workspace keys supply project environment variables. When projects are missing a saved value, Integrations lists them so you can update them one at a time or all at once. An updated project shows **Saved · on next start**: new projects and projects waking from a pause pick up the value, and a project running now keeps its current value until it next starts.

For a value specific to one application, use [Project setup → API Keys](/coding-agent/integrations/env-vars). Verify the running application's behavior after updating a credential; some integrations also need provider-side configuration.
