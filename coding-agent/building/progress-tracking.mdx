The roadmap organizes available planning artifacts into milestones, stories, and subtasks. Use `/kanban` or `/roadmap`, or open **Plan → Roadmap**. A project needs roadmap data for this view; a direct build may not have generated it.

## How progress is counted

Progress counts the features of your plan, not tasks. Stories that build the same feature are grouped under it, and the number reads as features built out of features planned, for example **3 of 4 built**. Work you set aside or take out of scope does not count against it.

Open **App map** in your project to see each feature with its status:

| Status | Meaning |
| --- | --- |
| Planned, not built | No run has built it yet |
| In progress | A run started it and has not finished it |
| Built, not checked yet | A run built it, and no check has run on it yet |
| Works, checked … ago | A check that exercises the feature passed |
| Changed since last check | The code it depends on changed after its last passing check |
| Needs a look | Its check failed once |
| Not working | Its check keeps failing |
| Stopped working | Its check passed before and fails now |
| Out of scope | Taken out of the plan |

"Works" only ever comes from a passing check. A feature a run built but nothing has checked stays **Built, not checked yet**. The map also shows what changed since the start or since yesterday, the screens in your app, and **Ready to launch**: what is still open before you publish, each with a plain fix.

## After each run

When a run that changed code finishes, a card in the chat summarizes it: what changed on screen, in your data and in your connections, whether the app runs and builds for publish, which features its checks confirmed, and the plan's progress, for example **3 of 4 built, 2 checked working**. If a feature that worked before stopped working, the card says so and offers to fix it.

## Build next

**Build next** and sprints pick the next feature from your plan: features that others depend on go first, then the plan's order. Work a sprint builds is recorded as **Built, not checked yet**, not as done, and it is never rebuilt just because no check has confirmed it. When **Build all** finishes, it says how many features are built and lists anything still planned.

A run cannot report a task as done while a check that passed when the run started fails at the end inside the code it changed. The agent keeps working on the regression, or reports the task as not verified.

## Kanban

| Column | Meaning |
| --- | --- |
| Backlog | Planned work that is not prioritized |
| Next Tasks | Upcoming work, including stories you prioritize |
| In Progress | Work that is active, or built and waiting for a check |
| Done | Work confirmed complete |

Where editing is enabled for your role and project, drag cards, reorder upcoming work, and open stories to edit their details. Some transitions are restricted during active builds. Status changes and incoming updates are reflected in the board.

A manually changed status records a planning decision. Use the run's messages, diff, and [verification evidence](/coding-agent/building/acceptance-criteria) to establish what was implemented and tested.

## Timeline and artifacts

Switch to **Timeline** for the Gantt view of milestones, stories, estimates, and progress. Screenshots attached to milestones can be opened in the gallery when captures are available.

Planning estimates describe expected effort. They are not deadlines or a promise that a live agent run will take the displayed number of hours.

## Sync to a project management tool

Use the roadmap's sync controls with a connected Linear or Jira account. Review the selected provider workspace and the sync result. When the roadmap changes, the interface can offer **Sync new changes**.

This workflow pushes the pre.dev roadmap to the external tool. Do not assume arbitrary edits in the external tool automatically update the pre.dev plan. GitHub code synchronization is a separate [repository workflow](/coding-agent/projects/github-integration).

## Follow active work

The session feed shows current actions, questions, errors, and results. Notifications can link back to a question, missing configuration, or completed work. Return to the session to inspect its latest status before starting duplicate work.
