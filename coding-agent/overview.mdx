Describe a change, give the agent the project context it needs, and review the code and evidence it produces. pre.dev supports new apps, existing repositories, planning, implementation, browser verification, and publishing.

The agent decides how to handle each request: it can answer a question, make a direct change, or plan a larger task before it builds. Ask for a plan in your message when you want to shape requirements and architecture first.

## Make the first request useful

Give the agent an outcome it can implement and you can verify:

```text
Add assignee and status filters to the issue board.
Keep the existing card layout. Filters should work together,
and an empty result should offer a way to clear them.
```

For existing code, include what happens today and what should change. For a new app, start with one working flow before expanding the scope.

## Choose your workspace

| Surface | Best starting point |
| --- | --- |
| Web | Create a project, import GitHub code, review plans, preview, and publish |
| CLI | Work directly in a local checkout and review changes with your usual Git tools |
| Architect API or MCP | Generate specifications for another development workflow |

The web and CLI share project records, planning artifacts, and account settings where supported. A session can run on your laptop through the CLI or in the cloud; see [sessions](/coding-agent/building/sessions-and-parallel-agents#where-a-session-runs).
