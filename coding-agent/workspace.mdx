The project workspace brings the agent conversation, code, and project artifacts into one place. Use the session tabs to switch workstreams and the view switcher to inspect the current project.

## Views

| View | Shortcut | What it shows |
| --- | --- | --- |
| Agent | Cmd/Ctrl + 1 | Chat, tool activity, and the current run |
| Plan → Overview | | Project summary and progress |
| Plan → Roadmap | Cmd/Ctrl + 2 | Milestones, stories, and timeline |
| Plan → Architecture | Cmd/Ctrl + 3 | System and user-flow graphs |
| Plan → Spec | Cmd/Ctrl + 4 | Specification documents |
| Code | Cmd/Ctrl + 5 | Source files and Git information |
| Preview | | The running app with your latest changes |

Roadmap, Architecture, and Spec appear when their artifacts exist. A direct build can have working code before it has a roadmap or architecture graph.

The header also holds **Share** and **Publish**. [Publish](/coding-agent/building/publish) puts the app at its permanent address.

## Inspect and edit code

Code opens as a viewer for browsing generated files. Select a file in the tree,
or search file names and contents. Content matches jump to the matching line.
On mobile, use the folder button to open the file drawer.

Use the toolbar to wrap long lines or copy the complete file. Large files open
in plain text to stay responsive; choose **Syntax highlighting** to enable colors.
Changes appear as unified diffs, with an optional split view on desktop.

Choose **Edit** for a manual change. Undo, redo, find and replace, and **Reset file**
are available while editing. Switching files keeps your drafts and undo history.
Choose **Save changes** to save, and **Done** to return to viewing. Done does not
save pending changes. If saving fails, the draft stays available so you can retry.

| Editing shortcut | Action |
| --- | --- |
| Cmd/Ctrl + F | Find in the current file |
| Cmd/Ctrl + Alt + F | Find and replace |
| Cmd/Ctrl + S | Save changes |

The editor supports basic changes without autocomplete, diagnostics, or code folding.

## Chat controls

Type `/` in the composer to see the commands for the current project.

| Command | Action |
| --- | --- |
| `/model` | Choose models for chat, research, coding, and acceptance |
| `/effort` | Set sprint effort to auto, low, medium, or high |
| `/balance` | View remaining credits |
| `/sprint <feature>` | Start a dedicated sprint in a new session |
| `/integrations` | Open Project setup |
| `/share` | Open sharing controls |
| `/kanban`, `/roadmap`, `/arch` | Open planning views, when the project has them |

The composer also shows the credits used on the project; select it for a turn-by-turn breakdown. The [CLI command reference](/cli/commands) lists terminal commands and keys; the web and CLI palettes differ.

## Project setup

Open `/integrations` or the composer's **+** menu. **Project setup** has the same tabs as workspace [Integrations](/coding-agent/integrations/overview), for this project:

- **Built-in**: AI, the project's payments mode (test or live), and its sign-in app.
- **Connections**: choose a workspace account for each provider.
- **Agent Skills**: reusable instructions for the agent.
- **MCP Servers**: additional tools and data sources.
- **API Keys**: the project's environment variables.

## Sessions and sharing

A session has its own conversation and branch of work. The active session determines what you are inspecting. Presence indicators show which session collaborators are viewing.

Use **Share** to invite collaborators and copy links to the app. See [sessions](/coding-agent/building/sessions-and-parallel-agents) and [collaboration](/coding-agent/building/collaboration).
