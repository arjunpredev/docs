## 2026-10-12

### Chat-only projects, in one Projects list

- Every folder you run `predev` in is a project. A folder without code starts **chat only**: the agent and all of its tools, with no keys, database, or file sync until you build something there. It becomes a **full project**, with Plan, Code, and Preview, when the agent writes code, a plan or build starts, or you type `/project`. See [Chat-only and full projects](/cli/chat-only-projects).
- On the web, chat-only projects are in your Projects list with a **Chat only** tag and where they run, and the separate Sessions list is gone. A chat-only project you opened but never wrote in stays out of the list.
- A chat-only project's page has a **Chat only** tag, shows Plan, Code, and Preview switched off, and has a **Make it a full project** button; they switch on in the open page when it becomes one.
- In the CLI, the top bar shows **chat only** until the project is full, the first line says what that means, and `predev --help` describes both.

## 2026-10-11

### Sessions that move to the cloud can build

- When a session's message runs in the cloud (**Run in the cloud instead** on the web), its cloud workspace starts with it. Once the agent writes code or starts a build there, the session becomes a project and **Code** and **Preview** appear.

## 2026-10-10

### CLI: sessions and projects

- **A folder without code opens a session.** `predev` in a folder with no code, or in your home folder, Desktop, Downloads, or Documents, starts a session: a chat tied to that folder, with all of the agent's tools, `/chrome` and `!` commands included. A session writes no keys to `.env`, starts no local database, syncs no files, sets up no git, makes no build suggestions, and does not appear in Projects. See the [pre.dev CLI](/cli/overview).
- A folder that holds code (a git repo, an app manifest, or source files), a folder already linked to a project, and `predev open <project>` open a project as before.
- **A session becomes a project when building starts**: the agent writes code into the folder, a plan or build starts, or you run `/publish` or `/project`. The CLI says so in one line and starts what was off.
- A project made from a session, or with `/project` in an empty folder, gets only the keys you set for the project in its `.env`.
- `predev open <session>` opens a session in the folder it last ran in, or in `~/predev-sessions/<name>` when that folder is gone.

### Sessions on the web

- A **Sessions** page, next to Projects, lists your CLI sessions with where each one is (working, online, offline, or in the cloud), messages waiting for it, its last message, and a search.
- **New session** starts pre.dev on your computer, or shows the command to run. Each session can be opened on your computer, renamed, made a project, or deleted.
- A session's page is the agent chat alone: no Plan, Code, Preview, or Publish until it becomes a project. Messages sent while your computer is offline wait for up to 7 days and run when the CLI opens again, or choose **Run in the cloud instead**.
- An answer to the agent's question given on the web goes to the computer that asked it and closes the question there.

### Browser Agents Local in the CLI starts faster

- [`@predotdev/mcp`](https://www.npmjs.com/package/@predotdev/mcp) 2.2.2 adds `npx -y @predotdev/mcp install-app`, which installs or updates the self-updating copy with no sign-in and no change to your agents' settings. The CLI runs it in the background, so `/chrome` starts without an npm lookup. See [Browser Agents Local in the CLI](/browser-agents/local#use-it-in-the-cli).
- In the CLI, the agent is no longer offered screenshot tools from local MCP servers, since it receives their text only.
- `!cmd` keeps square brackets exactly as typed.

## 2026-10-09

### pre.dev MCP 2.1.6 to 2.2.1

- **Setup works before you sign in.** `npx -y @predotdev/mcp setup` installs the server, adds it to your agents, and connects to Chrome first, then asks you to sign in. Press Enter to skip; `chrome_act`, plain-words waits, and the cloud tools work after `npx -y @predotdev/mcp login`. See [Browser Agents Local](/browser-agents/local#quick-start).
- **Pages are loaded when tools return.** `chrome_open` and `chrome_navigate` wait for the new page, clicks and key presses give it up to 2 seconds to update, and `chrome_wait` with only a tab waits until the page stops changing. Open and navigate end with **Page loaded**, or say the page is still loading after 20 seconds.
- **Leaner reads.** `chrome_read` leaves out site menus, footers, off-screen panels, and the options of long dropdowns (`full=true` keeps them). `selector` reads only the matching elements and `links` adds their URLs. Link URLs lose tracking parameters, and sponsored redirects resolve to where they lead.
- A `chrome_read` selector that matches nothing, or a `chrome_wait` selector that times out, lists the page's repeated items with selectors that work.
- Results name the Chrome profile, and a call without `tab` uses the tab this agent last worked in.
- **The installed copy updates itself.** It checks npm at most every 6 hours and verifies the download, and the running server uses the new version from its next call. Set `PREDEV_MCP_AUTO_UPDATE=off` to turn this off.

### CLI

- Text pasted on the first screen (**What do you want to build?**) no longer disappears.

It uses your CLI login and needs Node.js 22 or later. `/chrome off` turns it off. See [Browser Agents Local in the CLI](/browser-agents/local#use-it-in-the-cli).

- When a local MCP server returns an image, such as a screenshot, the CLI saves it as a file and gives the agent its path.

### The pre.dev MCP in every agent

See [manual setup](/browser-agents/local#manual-setup) for the rest.

### Switch from Claude in Chrome

- **[Switch from Claude in Chrome](/browser-agents/switch-from-claude-in-chrome)**: move your coding agent to Browser Agents Local in two steps, with a tool-by-tool map from Claude in Chrome's tools to the `chrome_*` tools. Your Chrome profiles, tabs, and logins carry over.

### pre.dev MCP 2.1.2 and 2.1.3

- `chrome_open` and `chrome_navigate` read `localhost:3000` and other host-and-port addresses as hosts, and open local and private-network addresses over http.
- Plain-words waits see the page's fields, as `chrome_act` does.
- Plain-words actions mask password, card, security code, one-time code, and secret-named fields, and drop token-like values from URLs, before anything is sent to pre.dev. See [Safety](/browser-agents/local#safety).
- The server's files under `~/.predev/mcp` are readable only by you, and `chrome_upload` and `file://` opens refuse SSH keys, cloud credentials, `.env` files, the saved pre.dev key, and Chrome's own data.

### AI Gateway: auto-recharge before a 402

- When a `/v1` call finds the workspace short of credits and auto-recharge is on, pre.dev refills first and runs the call instead of answering `402`. See [Errors](/api-reference/errors).
- The `topup_url` in an `insufficient_credits` error, `https://pre.dev/billing`, now opens the plans for a free account and credits for a subscriber.
- `insufficient_credits` carries `trial_blocked` when the workspace's free credits are on hold, for example until its email is verified. Plain-words actions then say to verify the email.

### Plan mode on every plan, and one stop at 0 credits

- `/plan` works on free plans too, in the web workspace and the CLI. At 0 credits a plan is refused before any work starts, with **Subscribe** or **Buy credits** next to it.
- The composer's plan chip shows only while plan mode is on, to turn it off; turn plan mode on with `/plan`.
- Out of credits, the chat shows one card with one line and one button: **Subscribe** or **Buy credits** while the balance is empty, then **Resume** once credits are back. A refused message, a paused preview, and a stopped publish name the same fix.
- On a project another account pays for (its owner, or a team), the chat checks and shows that account's balance.

## 2026-10-06

### The pre.dev MCP server: one command, every pre.dev tool, and your own Chrome

- **One command sets it up.** `npx -y @predotdev/mcp setup` signs you in to pre.dev in the browser, or creates a free account, and adds the pre.dev MCP server to every coding agent it finds on your Mac: Claude Code, Codex, Cursor, Windsurf, VS Code, Gemini CLI, OpenCode, and Claude Desktop. It registers the server as `predev` and connects to Chrome. Running it again updates to the newest version. See [Connect the MCP server](/architect-agent/mcp-setup).
- **Every pre.dev tool in one server.** The local server passes through the hosted tools on your key: `browser_agent`, `browser_agent_get`, `browser_agent_list`, `fast_spec`, `deep_spec`, `get_spec`, `list_specs`, and `get_plan`. Setup replaces a pre.dev server you added before, such as the hosted one, because the local server carries all of its tools. The hosted server at `https://api.pre.dev/mcp` keeps working for clients without Node.js.
- **[Browser Agents Local](/browser-agents/local): your own Chrome.** 17 `chrome_*` tools let your coding agent drive the Google Chrome you already have open: every profile, your logins, and your open tabs. All your agents share one connection, so Chrome asks **Allow remote debugging?** once each time it starts. See [Cloud or Local](/browser-agents/local#cloud-or-local) to choose.
- **Plain-words actions**: `chrome_act` clicks or types into an element you describe, and `chrome_wait` can wait for a plain-words `condition`. They use your workspace credits and appear in [`GET /v1/usage`](/ai-gateway/api/usage) as `browser-agents-local`. Every other Chrome tool runs on your computer and never calls pre.dev.
- Free and open source under MIT: [`@predotdev/mcp`](https://www.npmjs.com/package/@predotdev/mcp) on npm, source at [predotdev/mcp](https://github.com/predotdev/mcp). `check` confirms the setup, `login` signs in again, and `uninstall` removes it from every agent.

### Plans list additions under their feature

- In [`GET /get-plan`](/architect-agent/api/get-plan), the MCP [`get_plan`](/mcp/tools#get_plan) tool, and the `plan` in [spec status](/architect-agent/api/spec-status) and `get_spec`, work added to a feature that was already built is listed right after that feature, with `partOf` naming it, and counts as its own item until it is built. On a feature, `partOf` is `null`.
- The Markdown summary says `(added to <feature>)` and counts features and additions separately.

### Plan mode is back on the web

- On paid plans, the **Plan** chip and `/plan` turn on plan mode in the web workspace again, and `/auto` turns it off.
- Plan mode now stays on until you leave it. Each message changes the plan instead of the code and ends with a **Plan updated** card: the stories added, changed, or removed, the spec version, and the credits used. **Build it** leaves plan mode and starts building. `/plan` in the CLI works the same way.
- A first message that asks for a plan and no build yet, such as "Plan only, don't build yet: a habit tracker", plans the app without building it and opens the Plan view on a **Plan ready** card.
- The Plan view's tabs (Overview, Document, Roadmap, Architecture, Spec, App map, and Changes) read the same plan, and each says when it last changed.

## 2026-10-05

### Project plans through the API and MCP

- **[`GET /get-plan`](/architect-agent/api/get-plan)** returns a project's verified plan by `specId` or `projectId`: what the app is for, each feature's status from pre.dev's checks, progress, Ready to launch with a plain fix for each open item, and where screens, API routes and stored data live in the code. Add `format=markdown` to get the Markdown summary alone.
- **The MCP server has a `get_plan` tool** with the same plan, for a coding agent to read before it works on a project. See [get_plan](/mcp/tools#get_plan).
- [Spec status](/architect-agent/api/spec-status) and `get_spec` carry the plan as `plan` once a spec is completed.
- Reading a plan uses no credits.

### Progress counts features, and "works" comes from checks

- Progress now counts the features of your plan (for example **3 of 4 built**), and the **App map** shows each feature's status, from **Planned, not built** to **Works, checked … ago**. See [How progress is counted](/coding-agent/building/progress-tracking#how-progress-is-counted).
- A card after each run shows what changed, whether the app runs and builds, and which features its checks confirmed.
- **Build next** picks the next feature from the plan, and work a sprint builds stays **Built, not checked yet** until a check confirms it.

## 2026-09-27

### CLI: sign in with an API key, and run one task with `predev run`

- **Sign in without a browser.** Set `PREDEV_API_KEY` to your workspace API key and the CLI signs in with it when the computer has no saved login, as in CI, coding agents and fresh machines. A saved browser login still wins. See [Sign in without a browser](/cli/overview#sign-in-without-a-browser).
- **`predev run "<prompt>"`** sends one request to the agent in the current directory, prints the result, and exits: `0` finished, `1` failed or stopped, `2` not signed in or the key was rejected. With no prompt argument it reads the prompt from stdin. See [Run one task without the app](/cli/overview#run-one-task-without-the-app).
- **`predev logout`** forgets the saved login on this computer, so the CLI signs in with `PREDEV_API_KEY` when it is set.

### Documentation for agents

*Documentation update. No product change.*

- **[Guide for agents](/agents)** covers the interfaces, the API key, plan access, five complete recipes, polling and error rules, and limits. It comes first in [llms-full.txt](https://docs.pre.dev/llms-full.txt).
- **[llms.txt](https://docs.pre.dev/llms.txt)** is written by hand: agent entry points first, then every page by tab with a unique title.
- **[skill.md](https://docs.pre.dev/skill.md)** is reviewed by hand. Install it with `npx skills add https://docs.pre.dev`.
- **The AI Gateway has an OpenAPI file**, [ai-gateway.openapi.json](https://docs.pre.dev/api-reference/ai-gateway.openapi.json), covering all 25 `/v1` operations with error examples. Every operation has a reference page, and every REST response in [openapi.json](https://docs.pre.dev/api-reference/openapi.json) now has an example.
- The docs search server for agents is at `https://docs.pre.dev/mcp`.

### AI Gateway: a model list without a key, credit-only prices, and workspace-scoped files

- [`GET /v1/models/public`](/ai-gateway/api/public-models) lists every model an app can call, with its lab, type and modalities, and needs no API key. Credit prices stay on `GET /v1/models`.
- The catalog listings carry prices in credits only, in each row's `predev` object. When the catalog cannot be read, they answer `502` with code `catalog_unavailable`.
- [`GET /v1/usage`](/ai-gateway/api/usage) reports requests, credits and tokens only, and `workspace` is an opaque `ws_…` id.
- [`GET /v1/files`](/ai-gateway/api/list-files) lists only files this workspace uploaded, 20 per page by default and at most 50, paged with `after`.
- Video jobs are polled and downloaded by the `id` their submit response returns.
- A request that refers to another workspace's file, response, or video job returns `404` before anything runs.

### MCP tools say what they do and cost

- Tool descriptions and [`/mcp/info`](https://api.pre.dev/mcp/info) say what each tool does, when it helps, and what it costs. `get_spec` and `list_specs` use no credits.
- `get_spec` returns `creditsUsed`: the credits recorded so far for the spec's project.

## 2026-09-23

### AI Gateway: choose a model, not a provider

- Responses carry pre.dev generation ids (`pdg-…`), which [`GET /v1/generation`](/ai-gateway/api/generation) accepts. `usage` no longer includes cost fields: read the charge from `x-predev-credits-charged`, or from `GET /v1/generation` for a streamed call.
- A `provider` object in a request is ignored, and `/v1/providers` and the per-model endpoints lists are gone. Choose a model id from `GET /v1/models`, and send `models` for fallbacks.
- Errors from the model keep their status and message.

### Browser Agents: leaner results

- Task results and events no longer include `totalTokenUsage` or `llmCallsUsed`. Data, credits, status and step counts are unchanged.

## 2026-09-22

### Publish apps to a live address

- **Publish** in the project header builds a production version of the app at its own pre.dev address, or your own domain. Every publish is kept as a version, and you choose who can open it.
- Ask the agent to publish or unpublish; it checks with you first.
- Share leads with two links: **Live**, the published app, and **Draft**, your latest changes.
- Free plans publish for 7 days; Premium and above keep apps live and can add a custom domain. See [Publish](/coding-agent/building/publish).

### WebMCP

- Forms and actions the agent builds are registered as WebMCP tools that run the same handler as the button, so AI agents in the browser can use your app directly.
- Browser Agents call a site's WebMCP tools when it registers them, and work the page as before when it does not.

## 2026-09-16

### AI Gateway: hundreds of models inside every app

- `https://api.pre.dev/v1` serves hundreds of models from every major lab through one OpenAI-compatible API, plus the Messages format: chat, Responses, embeddings, rerank, images, video, speech and music, transcription, and files.
- Every project built on pre.dev gets the workspace key as `PREDEV_API_KEY`, and calls are charged to the workspace's credits. The catalog at `GET /v1/models` lists credit prices per model. See the [AI Gateway](/ai-gateway/overview).

### One API key per workspace

- Each workspace, personal or team, has one fixed key that starts with `pdk_`. It authenticates the REST API, the MCP server, Browser Agents and the AI Gateway. Existing keys keep working.
- Rotating the key keeps the old one valid for 15 minutes.

### Payments built in

- Apps built on pre.dev take payments with no setup: checkout, subscriptions and webhooks work in test mode while you build. To take real payments, connect an account you own and switch a project from test to live. See [payments](/payments/overview).

### Faster code browsing, with editing when you need it

- **Code opens as a viewer.** Browse generated files, search names and contents, copy code, and inspect unified or split changes without loading a full editor.
- **Choose Edit for manual changes.** Find and replace, undo and redo, reset, and saving remain available. Switching files keeps drafts; failed saves can be retried.
- **Large files stay responsive.** They open in plain text with optional syntax highlighting. Mobile uses a file drawer and wrapped unified diffs.

See [The workspace](/coding-agent/workspace#inspect-and-edit-code) for the controls and shortcuts.

### Browser Agents: typed billing errors with `actionUrl`

Non-2xx responses for [`POST /browser-agent`](/browser-agents/api/run-task)
now carry a structured body:

```json
{
  "error": "Need ~0.5 credits, have 0.00. Buy more to continue.",
  "code": "INSUFFICIENT_CREDITS",
  "actionUrl": "https://pre.dev/projects/browser-agents?upgrade=credits"
}
```

`code` is one of `SUBSCRIPTION_REQUIRED`, `INSUFFICIENT_CREDITS`,
`RATE_LIMITED`, `QUEUE_FULL`, `BATCH_TOO_LARGE`. `actionUrl` (when
present) deep-links the user back to pre.dev with the right billing
modal pre-opened. `window.open(actionUrl)` is enough to send the user
to the credit-purchase or subscription flow without any extra UI.

The same body is emitted on the SSE `error` event when streaming.

#### Node SDK: `predev-api@1.1.0`

```ts
import { InsufficientCreditsError, SubscriptionRequiredError } from 'predev-api';

try {
  await client.browserAgent(tasks);
} catch (e) {
  if (e instanceof InsufficientCreditsError) window.open(e.actionUrl);
  else if (e instanceof SubscriptionRequiredError) window.open(e.actionUrl);
}
```

New typed exceptions: `SubscriptionRequiredError`,
`InsufficientCreditsError`, `QueueFullError`, `BatchTooLargeError`. All
non-breaking: existing `instanceof PredevAPIError` checks still match.
See the [Node SDK error-handling docs](/architect-agent/sdks/node#errors).

#### Python SDK: `predev-api==1.1.0`

```python
from predev_api import InsufficientCreditsError, SubscriptionRequiredError
import webbrowser

try:
    client.browser_agent(tasks)
except InsufficientCreditsError as e:
    if e.action_url: webbrowser.open(e.action_url)
except SubscriptionRequiredError as e:
    if e.action_url: webbrowser.open(e.action_url)
```

New exceptions mirror the Node SDK with `action_url` field. See the
[Python SDK error-handling docs](/architect-agent/sdks/python#errors).
