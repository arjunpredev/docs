## 2026-09-27

### CLI: sign in with an API key, and run one task with `predev run`

- **Sign in without a browser.** Set `PREDEV_API_KEY` to your workspace API key and the CLI signs in with it when the computer has no saved login, as in CI, coding agents and fresh machines. A saved browser login still wins. See [Sign in without a browser](/cli/overview#sign-in-without-a-browser).
- **`predev run "<prompt>"`** sends one request to the agent in the current directory, prints the result, and exits: `0` finished, `1` failed or stopped, `2` not signed in or the key was rejected. With no prompt argument it reads the prompt from stdin. See [Run one task without the app](/cli/overview#run-one-task-without-the-app).
- **`predev logout`** forgets the saved login on this computer, so the CLI signs in with `PREDEV_API_KEY` when it is set.

### Documentation for agents

*Documentation update. No product change.*

- **[Guide for agents](/agents)** covers the interfaces, the API key, plan access, five complete recipes, polling and error rules, and limits. It comes first in [llms-full.txt](https://docs.pre.dev/llms-full.txt).
- **[llms.txt](https://docs.pre.dev/llms.txt)** is written by hand: agent entry points first, then every page by tab with a unique title.
- **[skill.md](https://docs.pre.dev/skill.md)** is reviewed by hand. Install it with `npx skills add https://docs.pre.dev`.
- **The AI Gateway has an OpenAPI file**, [ai-gateway.openapi.json](https://docs.pre.dev/api-reference/ai-gateway.openapi.json), covering all 25 `/v1` operations with error examples. Every operation has a reference page, and every REST response in [openapi.json](https://docs.pre.dev/api-reference/openapi.json) now has an example.
- The docs search server for agents is at `https://docs.pre.dev/mcp`.

### AI Gateway: a model list without a key, credit-only prices, and workspace-scoped files

- [`GET /v1/models/public`](/ai-gateway/api/public-models) lists every model an app can call, with its lab, type and modalities, and needs no API key. Credit prices stay on `GET /v1/models`.
- The catalog listings carry prices in credits only, in each row's `predev` object. When the catalog cannot be read, they answer `502` with code `catalog_unavailable`.
- [`GET /v1/usage`](/ai-gateway/api/usage) reports requests, credits and tokens only, and `workspace` is an opaque `ws_…` id.
- [`GET /v1/files`](/ai-gateway/api/list-files) lists only files this workspace uploaded, 20 per page by default and at most 50, paged with `after`.
- Video jobs are polled and downloaded by the `id` their submit response returns.
- A request that refers to another workspace's file, response, or video job returns `404` before anything runs.

### MCP tools say what they do and cost

- Tool descriptions and [`/mcp/info`](https://api.pre.dev/mcp/info) say what each tool does, when it helps, and what it costs. `get_spec` and `list_specs` use no credits.
- `get_spec` returns `creditsUsed`: the credits recorded so far for the spec's project.

## 2026-09-26

### Agent Skills and sign-in for MCP servers

- **Skills follow the Agent Skills format.** Paste a `SKILL.md` or upload a skill folder as a `.zip`. The agent sees each skill's name and description and loads the rest only when a task needs it.
- **Remote MCP servers can sign in with OAuth.** Add the server's `https` URL in Integrations and approve access, instead of pasting a token.
- Local command (stdio) MCP servers run only from the CLI; the web workspace uses remote servers.

### A project header that fits any window

- The header no longer overflows at narrow widths. The **Sandbox** chip shows its status, with CPU and memory on hover, and **Publish** is a rocket icon.
- Clicking the Sandbox chip explains where the project runs and how to work on it from a terminal: install the CLI, then `predev open`.

## 2026-09-25

### Plan mode removed on the web

- The web workspace no longer has a Plan toggle or the `/plan` and `/auto` commands. The agent decides when to plan before it builds.

### CLI: publish, usage, undo, and more

- `/publish` and `/unpublish` put the app on its live address or take it down.
- `/usage` lists what the project's credits went on, turn by turn.
- `/undo` and `/redo`, with a checkpoint before every run on your machine.
- `/rename`, `/logout`, `/mcp add` and `/skills add`.
- Up and down arrows recall earlier prompts, each session tab keeps its draft, and suggested next messages appear after a turn.

## 2026-09-23

### AI Gateway: choose a model, not a provider

- Responses carry pre.dev generation ids (`pdg-…`), which [`GET /v1/generation`](/ai-gateway/api/generation) accepts. `usage` no longer includes cost fields: read the charge from `x-predev-credits-charged`, or from `GET /v1/generation` for a streamed call.
- A `provider` object in a request is ignored, and `/v1/providers` and the per-model endpoints lists are gone. Choose a model id from `GET /v1/models`, and send `models` for fallbacks.
- Errors from the model keep their status and message.

### Browser Agents: leaner results

- Task results and events no longer include `totalTokenUsage` or `llmCallsUsed`. Data, credits, status and step counts are unchanged.

## 2026-09-22

### Publish apps to a live address

- **Publish** in the project header builds a production version of the app at its own pre.dev address, or your own domain. Every publish is kept as a version, and you choose who can open it.
- Ask the agent to publish or unpublish; it checks with you first.
- Share leads with two links: **Live**, the published app, and **Draft**, your latest changes.
- Free plans publish for 7 days; Premium and above keep apps live and can add a custom domain. See [Publish](/coding-agent/building/publish).

### WebMCP

- Forms and actions the agent builds are registered as WebMCP tools that run the same handler as the button, so AI agents in the browser can use your app directly.
- Browser Agents call a site's WebMCP tools when it registers them, and work the page as before when it does not.

## 2026-09-17

### Integrations opens on a Built-in tab

- The workspace API key, the model catalog and payments are on **Integrations → Built-in**. Each project's settings has a Test or Live switch for payments.

## 2026-09-16

### AI Gateway: hundreds of models inside every app

- `https://api.pre.dev/v1` serves hundreds of models from every major lab through one OpenAI-compatible API, plus the Messages format: chat, Responses, embeddings, rerank, images, video, speech and music, transcription, and files.
- Every project built on pre.dev gets the workspace key as `PREDEV_API_KEY`, and calls are charged to the workspace's credits. The catalog at `GET /v1/models` lists credit prices per model. See the [AI Gateway](/ai-gateway/overview).

### One API key per workspace

- Each workspace, personal or team, has one fixed key that starts with `pdk_`. It authenticates the REST API, the MCP server, Browser Agents and the AI Gateway. Existing keys keep working.
- Rotating the key keeps the old one valid for 15 minutes.

### Payments built in

- Apps built on pre.dev take payments with no setup: checkout, subscriptions and webhooks work in test mode while you build. To take real payments, connect an account you own and switch a project from test to live. See [payments](/payments/overview).

### Faster code browsing, with editing when you need it

- **Code opens as a viewer.** Browse generated files, search names and contents, copy code, and inspect unified or split changes without loading a full editor.
- **Choose Edit for manual changes.** Find and replace, undo and redo, reset, and saving remain available. Switching files keeps drafts; failed saves can be retried.
- **Large files stay responsive.** They open in plain text with optional syntax highlighting. Mobile uses a file drawer and wrapped unified diffs.

See [The workspace](/coding-agent/workspace#inspect-and-edit-code) for the controls and shortcuts.

### Browser Agents: typed billing errors with `actionUrl`

Non-2xx responses for [`POST /browser-agent`](/browser-agents/api/run-task)
now carry a structured body:

```json
{
  "error": "Need ~0.5 credits, have 0.00. Buy more to continue.",
  "code": "INSUFFICIENT_CREDITS",
  "actionUrl": "https://pre.dev/projects/browser-agents?upgrade=credits"
}
```

`code` is one of `SUBSCRIPTION_REQUIRED`, `INSUFFICIENT_CREDITS`,
`RATE_LIMITED`, `QUEUE_FULL`, `BATCH_TOO_LARGE`. `actionUrl` (when
present) deep-links the user back to pre.dev with the right billing
modal pre-opened. `window.open(actionUrl)` is enough to send the user
to the credit-purchase or subscription flow without any extra UI.

The same body is emitted on the SSE `error` event when streaming.

#### Node SDK: `predev-api@1.1.0`

```ts
import { InsufficientCreditsError, SubscriptionRequiredError } from 'predev-api';

try {
  await client.browserAgent(tasks);
} catch (e) {
  if (e instanceof InsufficientCreditsError) window.open(e.actionUrl);
  else if (e instanceof SubscriptionRequiredError) window.open(e.actionUrl);
}
```

New typed exceptions: `SubscriptionRequiredError`,
`InsufficientCreditsError`, `QueueFullError`, `BatchTooLargeError`. All
non-breaking: existing `instanceof PredevAPIError` checks still match.
See the [Node SDK error-handling docs](/architect-agent/sdks/node#errors).

#### Python SDK: `predev-api==1.1.0`

```python
from predev_api import InsufficientCreditsError, SubscriptionRequiredError
import webbrowser

try:
    client.browser_agent(tasks)
except InsufficientCreditsError as e:
    if e.action_url: webbrowser.open(e.action_url)
except SubscriptionRequiredError as e:
    if e.action_url: webbrowser.open(e.action_url)
```

New exceptions mirror the Node SDK with `action_url` field. See the
[Python SDK error-handling docs](/architect-agent/sdks/python#errors).
