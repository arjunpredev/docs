Both endpoints take a `model` and a `prompt` and return generated images or video. List the models with `GET /v1/images/models` and `GET /v1/videos/models`; both lists are free and not rate-limited and include a `predev` price object per row.

## Images

`POST /v1/images` returns generated images synchronously and is charged when the response is returned.

```bash
MODEL=$(curl -s https://api.pre.dev/v1/images/models \
  -H "Authorization: Bearer $PREDEV_API_KEY" | jq -r '.data[0].id')

curl --fail-with-body https://api.pre.dev/v1/images \
  -H "Authorization: Bearer $PREDEV_API_KEY" \
  -H "Content-Type: application/json" \
  -d "{\"model\": \"$MODEL\", \"prompt\": \"A lighthouse at dawn, watercolor\"}"
```

Use `credits_per_image` or the other `predev` prices in the model row to estimate cost; the actual charge follows the call's metered usage, like every other call.

## Video

Video generation is asynchronous:

1. [`POST /v1/videos`](/ai-gateway/api/video-jobs) submits the job and returns it with a `polling_url`.
2. [`GET /v1/videos/{jobId}`](/ai-gateway/api/video-status), the `polling_url`, reports status.
3. [`GET /v1/videos/{jobId}/content`](/ai-gateway/api/video-content) returns the finished video.

```bash
MODEL=$(curl -s https://api.pre.dev/v1/videos/models \
  -H "Authorization: Bearer $PREDEV_API_KEY" | jq -r '.data[0].id')

POLL=$(curl --fail-with-body -s https://api.pre.dev/v1/videos \
  -H "Authorization: Bearer $PREDEV_API_KEY" \
  -H "Content-Type: application/json" \
  -d "{\"model\": \"$MODEL\", \"prompt\": \"A paper boat drifting down a rain gutter\"}" | jq -r '.polling_url')

# poll until the status is terminal
while :; do
  STATUS=$(curl --fail-with-body -s "$POLL" -H "Authorization: Bearer $PREDEV_API_KEY" | jq -r '.status')
  case "$STATUS" in completed|failed|cancelled|expired) break ;; esac
  sleep 5
done

# then download
curl --fail-with-body "$POLL/content" \
  -H "Authorization: Bearer $PREDEV_API_KEY" -o video.mp4
```

Submitting a job needs at least 10 credits available. The job is charged once it finishes, not at submission: on the first status poll that reports completion, on the `/content` download if you never polled, or by pre.dev afterwards if you stopped polling. Poll until the status is terminal (`completed`, `failed`, `cancelled` or `expired`) before reading `/content`. Use the `polling_url` from the submit response as the job's address.

Jobs belong to the workspace that created them; another workspace's job id returns `404`.
